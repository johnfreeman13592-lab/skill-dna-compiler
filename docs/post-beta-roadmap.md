# Skill DNA Compiler Post-Betaロードマップ

この文書は公開後に検証する製品仮説であり、実装時期の確約ではない。最初のBetaは、明示選択
したObsidian／Markdownメモから、人間が根拠を確認したCodex Skillを作る狭い範囲を維持する。

## 製品の立場

Skill DNA Compilerはエージェント本体を置き換えない。現在使っているCodexやその他のAI開発
環境へ後付けし、過去の経験、判断、失敗、ルールを持ち運べる能力へ変換する中立レイヤーを
目指す。

中心メッセージ候補:

> 今使っているAIは、そのままでいい。Skill DNA Compilerが、あなたの経験を持ち運べる能力に変える。

## 公開直後 — 価値検証と迷いの削減

1. 初回チュートリアルと画面内の次操作案内を改善する。
2. 情報ソース候補をローカルで提案する。ただし外部送信対象へ自動追加しない。
3. DNA Traceの確認時間、保留理由、生成Skillの利用結果を計測する。
4. 不具合、用語、SmartScreen、API料金説明を実フィードバックから修正する。

## 既存環境へ安全に後付けする体験

第三者製品としての強みは、現在のAI開発環境から乗り換えさせないことにある。将来の導入
支援では、既存Skillと設定をローカルで検出し、変更差分、保存先、競合、戻し方を表示する。
ワンクリック導入を目指しても、ユーザーの承認なしに既存ファイルを上書きせず、出力後に
ロールバックできる契約を維持する。

## 次の中核実験 — Cross-Session Skill Discovery

一般的なSession-to-Skillだけを次機能にはしない。同じ題材を「メモのみ」と「明示選択した
会話・行動記録あり」で比較し、追加情報によって適用条件、禁則、失敗原因、既存Skillの更新点を
直接の根拠から発見できるか検証する。

提案は、新しいSkillを作る、既存Skillを更新する、Skill化しない、の3種類に分ける。候補数を
増やすことではなく、一般論や一度きりの内容を除外し、元資料にない推測を明示し、最終指示が
DNA Traceを通ることを成功条件にする。

価値が確認できるまでは、新しい入力adapter、DB移行、大きなUI、自動承認を追加しない。詳細な
A/B比較、安全境界、成功・中止条件は
[Cross-Session Skill Discovery実験計画](cross-session-skill-discovery-experiment.md)に記録する。

## その後の有力候補 — Skill関係グラフ

Obsidianのグラフ表示のように、Skill同士と根拠の関係をローカルで可視化する。

想定するnode:

- Skill DNAと各バージョン
- Skill候補
- 根拠文書
- プロジェクト
- 出力先エージェント

想定するedge:

- `derived_from`: この根拠から作られた
- `overlaps_with`: 指示や目的が重複する
- `conflicts_with`: 条件や禁止事項が矛盾する
- `supersedes`: 新しい版や判断が置き換えた
- `used_with`: 同じ作業で一緒に使われた
- `specializes`: 汎用Skillをプロジェクト向けに具体化した

最初はSQLiteにすでにあるID、版、出典、統合履歴から決定的に作れるedgeだけを表示する。
AI推測による関係は別表示にし、人間の確認なしに確定edgeへ変換しない。グラフは見た目だけで
なく、重複、矛盾、古いSkill、根拠の弱いSkillを見つける入口として評価する。

## その後の差別化候補

### Skill Health Check

重複、矛盾、古い参照、秘密情報、環境非互換、根拠不足を検出する。AIが生成した外部Skillも
検査対象にできれば、生成機能が一般化した後も品質管理ツールとして価値を持てる。

### Evidence付き横断抽出

複数の明示選択文書から共通パターンを探し、プロジェクト専用、ユーザー共通、公開可能な
汎用Skillへ分けて提案する。Git履歴、テスト、会話履歴、行動履歴は将来の入力候補だが、
権限とプライバシー設計を個別に行い、プロジェクト全体を無断で送信しない。

最初のCross-Session実験では、会話・行動記録を正式な入力形式として実装せず、ユーザーが
選んだ固定記録だけで価値を比較する。製品化する入力adapterは、比較結果と利用需要を確認して
から1種類ずつ選ぶ。

### Skill変換ハブ

Skill DNAを中立形式として維持し、Codex以外の出力adapterを需要に基づいて1つずつ追加する。
単純コピーではなく、利用可能ツール、ディレクトリ構造、指示形式の差を検査して警告する。

### Skill改善ループ

利用回数、再修正、テスト結果、ユーザー評価から改善候補を提示する。観察や提案を自動化しても、
Skillの更新、承認、出力は自動化しない。

### 引継ぎパッケージ

現在状態、設計判断、未完了タスク、過去の失敗、有効なSkillをまとめ、新しいAIチャットへ
必要な情報だけを持ち込む。単なる会話要約ではなく、適用すべきSkillと古い情報を区別する。

## 当面作らないもの

- 独自の万能AIエージェント
- 運営者サーバー前提のクラウド同期
- 自動承認・自動Skill書き換え
- 無断のリポジトリ・Vault全体分析
- マーケットプレイス、決済、チーム管理

公開後は機能数ではなく、DNA Traceの価値、既存環境へ追加しやすいこと、Skillを安全に
保守できることを優先して次の1機能を選ぶ。
