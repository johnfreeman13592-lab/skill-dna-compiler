# Skill DNA Compiler 実装計画

## 1. 現状

2026-07-17時点でリポジトリは空であり、既存コードや再利用可能なコンポーネントはない。添付された開発計画と配布・運営方針を製品仕様の基準とする。

## 2. MVPの完成状態

ユーザーがローカルのObsidian Vaultから明示的にメモを選び、AIへ送る文章を確認し、出典付きのSkill候補を取得できる。候補は編集、承認、拒否、保留でき、承認済み候補だけをSkill DNAとして保存し、プレビューと上書き確認を経てCodex用`SKILL.md`へ出力できる。

初回完成版は入力をObsidian／Markdown、出力をCodexに限定する。一般ユーザー向け製品を
目指すが、入力形式・出力先を増やすことで完成を遅らせない。将来はさまざまなメモアプリ、
テキスト・構造化データ形式、その他のエージェントへ広げる。NotionとJSONは例であり、
固定された次期対応先ではない。最初の製品価値を検証した後、実際の需要に基づいて
adapterを1つずつ追加する。

一般公開時の差別化仮説は「DNA Trace」とする。最終Skillの各指示を、明示選択された
元メモの正確な根拠、使用条件、禁則へ追跡し、人が確認でき、追跡・承認できない指示を
出力させない。保存済み`v0.1.0-beta.2`配布物は候補単位の出典までである。現在の開発
ブランチには指示単位Traceの最小実装が入り、3入力グループの実メモdogfoodと4件のSkill
前方テストを完了した。世界初などの表現は使わず、公開後も確認時間と実利用価値を測って
差別化仮説を更新する。

## 3. 配布・運営条件

- 最初の配布対象はWindows 10/11と仮定する。
- Windows以外のデスクトップOS対応は将来目標とするが、初回完成版には含めない。Linux系OSと
  macOSは例であり、固定された次期対象ではない。共通コアへOS依存処理を混ぜず、資格情報、
  単一起動ロック、ランチャー、パッケージ、署名、受入テストだけをplatform adapterとして
  需要に基づき追加する。
- GitHub Releasesから無料配布するが、公開操作はユーザー確認後に行う。
- 運営者サーバー、アカウント、決済、ライセンス認証、クラウド同期は実装しない。
- API利用料は利用者が負担し、モデルと入力上限を設定可能にする。
- Vault、インデックス、候補、Skill DNA、履歴、生成物はローカル保存する。
- 運営者への自動テレメトリーは送信しない。

## 4. 元計画から変更する点

### FastAPIをMVPから外す

Streamlit UIが同一プロセス内のアプリケーションサービスを呼ぶ。将来、外部クライアントやMCP対応が必要になった場合だけAPI境界を追加する。これにより二重の起動処理、ポート管理、CORS、配布サイズを避ける。

### APIキーの保存方式を分ける

- 開発環境：Git管理外の`.env.local`
- 一般配布版：OS資格情報ストア（Windows Credential Managerなど）
- SQLite、ログ、生成Skill：保存禁止

### 利用状況の検証方法を変更する

サーバーを持たないMVPでは自動集計を行わない。アプリ内にはメモ本文を含まないローカル統計を保持し、ユーザーが内容を確認したうえで任意にエクスポートできる設計を将来追加する。初期フィードバックはGitHubなどの外部窓口を別途決める。

### OpenAIモデルを設定化する

ソースコードへ固定しない。開発時の初期値は、知能とコストのバランス向けとして公式に案内されている`gpt-5.6-terra`、reasoning effortは`medium`とする。`gpt-5.6`は高性能・高価格の`gpt-5.6-sol`へ解決されるため、品質、構造化出力成功率、速度、APIコストを実データで比較してから公開版の既定値を決める。

## 5. フェーズ

### Phase 1 — 基盤

- Python 3.11の`src`レイアウト
- Pydantic設定と秘密値型
- 機密情報を伏せるログ
- SQLAlchemyとSQLiteスキーマ
- 基本ドメインモデル
- 最小Streamlit画面
- pytestとRuff

完了条件：仮想環境で依存関係を導入でき、DB初期化、設定、ドメインモデルのテストとLintが成功する。

### Phase 2 — Vault読み込み

- Vaultパスの明示選択
- `.md`の再帰探索と除外規則
- Frontmatter、見出し、内部リンクの解析
- ハッシュと更新日時
- 一覧、検索、絞り込み、プレビュー
- 元Vaultを変更しないテスト

### Phase 3 — 安全なAI抽出

- 秘密情報検出
- 選択文書と実送信内容のプレビュー
- provider interfaceとOpenAI Responses API実装
- Structured Outputsと厳格なスキーマ検証
- 文字数・概算トークン・入力上限
- タイムアウト、再試行、エラー表示、モック
- 出典の原文照合

### Phase 4 — 人間によるレビュー

- 候補一覧、詳細、編集（実装済み）
- 承認、拒否、保留（実装済み。状態保存のみ）
- 出典比較と警告（実装済み）
- 重複候補の検出と手動統合（実装済み）

編集可能な候補本文と、検証済みの出典を分離する。編集後は承認状態を必ず未確認へ戻す。Phase 4の承認操作は候補状態だけを変更し、Skill DNAやファイル出力を発生させない。

重複判定はローカルの決定的な類似度計算だけで行い、参考情報として表示する。自動統合は行わない。手動統合では元候補を削除せず保留にし、全出典を保持した新しい未確認候補と統合元履歴を保存する。

### Phase 5 — Skill DNA

- 承認済み候補だけを明示操作で変換（実装済み）
- 変換前後の比較プレビュー（実装済み）
- SQLite JSONへの現在版保存（実装済み）
- 状態、バージョン、出典、変更履歴の追跡（実装済み）

候補の承認操作だけではSkill DNAを作らない。別の確認付き変換操作で初版`0.1.0`を保存し、再変換時はpatch版を上げて過去のJSONスナップショットを保持する。Phase 5ではファイル出力を行わない。

### Alphaデータ保護（Phase 5開始前）

- SQLite `user_version`と`schema_migrations`によるスキーマv1〜v3管理（実装済み）
- 未バージョンDBの移行前自動バックアップ（実装済み）
- 整合性検査付きの手動バックアップと復元（実装済み）
- 復元前の現在DB自動退避と、アプリより新しいDBの拒否（実装済み）

バックアップはローカルのアプリデータ領域だけに保存する。復元は破壊的な可能性があるため、対象選択、警告、明示確認を必須とする。自動削除や世代数制限はMVPでは行わない。

### Phase 6 — Codex出力

- Codex必須frontmatterだけを持つ決定的な`SKILL.md`生成とプレビュー（実装済み）
- 64文字以内のslugとパス・シンボリックリンク安全性（実装済み）
- 既に存在する親フォルダの明示選択（実装済み）
- 上書きの追加確認、原子的なファイル置換、SQLite出力履歴（実装済み）

Phase 6はSkill DNAに保存された伏字・検証済み情報だけを使用し、API通信を行わない。出力予定パスと全文を表示し、確認前にはフォルダもファイルも作らない。

### Phase 7 — 公開品質

- 統合テストとセキュリティテスト
- サンプルVaultとデモSkill
- Windowsパッケージ、クリーンPC検証
- プライバシー文書、利用手順、フィードバック導線
- ライセンス決定後にGitHub公開とRelease作成

非公開のPhase 7Aとして、標準セキュリティ監査、再現可能なオフラインE2E、
クリーン一時環境検証、ローカル限定のSkill使用フィードバックを完了した。

非公開のPhase 7Bとして、Windows Credential Manager設定画面、`127.0.0.1`限定の
二重起動防止ランチャー、PyInstaller `onedir`、サンプルVault・利用文書同梱、
ポータブルZIPとSHA-256生成を実装した。ローカルのパッケージヘルスチェック後、
別Windows PCでのPython非依存確認と、配布版からの少額実API 1回を最終受入とする。
一般公開、ライセンス、インストーラー、コード署名は次の判断段階に残す。

2026-07-20、別Windows PCでオフライン主要フロー、Credential Managerの保存・再起動後取得・削除、
架空メモ1件の少額実API、テストデータのクリーンアップまで完了した。Phase 7Bおよび今回定義した
非公開Beta MVPは完成。証拠は`docs/beta-completion-audit.md`へ記録した。

## 6. 横断的な受入条件

- 選択していないメモをAPIへ送らない。
- API送信前に本文、検出警告、入力量を確認できる。
- 候補が空でも正常に処理できる。
- 全候補に検証可能な出典がある。
- 承認前にSkill DNAや`SKILL.md`を生成しない。
- APIキーとメモ本文をログへ出さない。
- 許可された出力先の外へ書き込まない。
- 同名ファイルを無確認で上書きしない。
- 主要単体テストと抽出から出力までの統合テストが成功する。

## 7. 後でユーザー確認が必要な事項

Phase 1を妨げないため、次の判断は実行直前に確認する。

1. Windows版完成後、実際の需要に基づいてどのOSを第2対象として検証するか。
2. OSSライセンス、ソース公開範囲、将来のPro版との関係。
3. ポータブルZIP、インストーラー、または両方の配布形式。
4. GitHubリポジトリの公開とGitHub Releasesへの公開。
5. ユーザーが任意送信できるフィードバック窓口。
